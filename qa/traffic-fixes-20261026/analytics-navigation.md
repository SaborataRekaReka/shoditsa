# Навигационная аналитика и View Transition: подготовленный фикс 26.10.2026

Исходная версия worktree — production web `a3fcf616`. Изменения подготовлены по диагностике `docs/research/analytics-2026-10-24/REPORT.md` и свежему аудиту 26 октября. Production не изменялся этим агентом.

## Изменения

- `RootView` учитывает только завершённую локацию маршрутизатора. Общий модуль дедуплицирует повторные эффекты и смены URL без изменения страницы; путь, режим и допустимые игровые фильтры входят в идентичность просмотра. Переход на другую серверную сессию учитывается отдельно, но её ID не экспортируется в URL Метрики.
- Метрика и first-party `page_view` используют одну точку отправки. `init({ defer: true })` отключает автоматический начальный hit, старый вызов из `App` удалён. Публичные URL без `#screen`; screen/mode остаются параметрами. Это измерительная граница относительно прежней статистики.
- До выбора согласия техническое событие остаётся в очереди. При первом согласии оно обогащается и отправляется один раз; повторное accepted не создаёт дубликата. При отказе Метрика выключена, атрибуция удаляется. При позднем rejected→accepted учитывается только новый текущий просмотр; отклонённая история не обогащается.
- Личные параметры, токены приглашений и произвольные query не входят в отправляемый маршрут. Разрешены названия режимов и ограниченные игровые period/date/difficulty/variant; UTM допускается только по прежнему consented allowlist и на первом ручном hit.
- Возвращены действия `select_mode`, `open_profile`, `open_archive`, клики карточек категорий с фактическим статусом. Это намерения навигации, не старты игры. В лобби видимый режим получает `mode_opened`, видимая настройка Захвата — прежний `territory_landing_view`. Новых целей в кабинете не создавалось.
- Кнопка «Настройки cookie» открывает существующий диалог в общем и главном подвалах.
- Версия клиентских событий и отчётов о контенте берётся из `meta[name=shoditsa-build-sha]` текущего HTML. Production без маркера помечается `unknown`, а не `dev`.
- Убрано общее `view-transition-name: study-aside` у потенциально нескольких панелей; они анимируются вместе с root. Имя навигации ограничено внешней оболочкой.
- Установленная версия TanStack Router отбрасывает объект native ViewTransition. Локальный адаптер instance hook сохраняет момент обновления и opt-out `viewTransition: false`, но передаёт все три promise общему обработчику. Отмена анимации не отменяет commit. Ошибки update и неожиданные ready/finished сохраняются как `client_error` с фазой; глобального фильтра ошибок нет. Использование `finished.finally()` без обработки производного rejection удалено, preview и cross-document используют того же наблюдателя.

## Проверки и ограничения

Статически проверены источники, отсутствие оставшихся активных `App.trackMetrikaScreen` / начального `initClientEvents.page_view`, область маршрутов и `git diff --check`. Автоматические suites не запускались по пожеланию пользователя. Общий typecheck/build выполняет root. Браузерное прохождение не выполнено этим агентом; фактическая доставка событий после релиза пока не подтверждена.

Браузерная приёмка: accepted → главная → рейтинг → профиль → архив → главная → Кино → Музыка → лобби → Захват → Клуб; ровно один hit/page_view на завершённый переход, отдельный hit при смене режима, без hit для якоря или повторного render. Прямой вход, Back/Forward и быстрые повторные переходы. Pending→accepted без двух первоначальных page_view; rejected без Метрики; повтор accepted без дубля; rejected→accepted без воспроизведения прошлых страниц. Cookie-кнопка на desktop/mobile. Во время быстрой навигации/скрытия вкладки не появляются unhandled rejection отменённых анимаций; при намеренной ошибке update диагностика не теряется. Проверка на изолированной среде не заменяет production transport check.

Технический контроль после релиза: новые `appVersion` соответствуют загруженному web SHA, нет дублей просмотра/доставки, consent coverage и серверные start/complete сохраняются. Динамику глубины/просмотров до и после этой границы нельзя объявлять продуктовым ростом. Бизнес-оценка — отдельное завершённое 14-дневное окно с учётом сопутствующих изменений.

Официальные основания: [Метрика для SPA](https://yandex.ru/support/metrica/ru/code/counter-spa-setup), [ViewTransition.ready](https://developer.mozilla.org/en-US/docs/Web/API/ViewTransition/ready), [updateCallbackDone](https://developer.mozilla.org/en-US/docs/Web/API/ViewTransition/updateCallbackDone), [finished](https://developer.mozilla.org/en-US/docs/Web/API/ViewTransition/finished).
