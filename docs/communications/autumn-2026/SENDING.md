# Отправка осеннего письма с сайта

Административная страница: https://shoditsa.ru/api/v1/admin/mailings/console. Нужна действующая сессия единственного администратора проекта. Страница использует обычные HTML-формы, без отдельного почтового сервиса и без нового клиентского приложения.

Отправитель: настроенный SMTP проекта, имя «Сходится!». Ответы приходят на breneize@yandex.ru. Картинки вложены с CID. HTML и plain text отправляются вместе, адреса других получателей не раскрываются.

Сначала администратор отправляет один тест себе. После приёма теста SMTP доступен запуск с указанием источника согласий. Пользователь подтвердил в этом чате 23 октября 2026 года, что отдельно собранные согласия на новости есть у всей базы зарегистрированных пользователей.

Первый запуск фиксирует аудиторию и хеш содержания `autumn-2026-v1`. Повторный запуск продолжает только оставшуюся очередь. Новые регистрации в уже запущенный выпуск не попадают. Учитываются зарегистрированные аккаунты, в том числе без подтверждения email. Анонимные, заблокированные, адреса без корректного формата и отписавшиеся исключаются. Адреса приводятся к нижнему регистру и не повторяются внутри выпуска.

Очередь хранится в PostgreSQL. Воркеры получают по одному письму под блокировкой строки кампании. Интервал между началами отправки составляет минимум 10 секунд. Перед SMTP повторно проверяются email аккаунта, блокировка, удаление и отписка. Пауза действует на ещё не начатые письма; уже передаваемое письмо может быть принято.

`accepted` означает только приём SMTP, а не доставку во входящие. Ошибки получателя сохраняются как `failed`. Обрыв соединения, потерянный ответ или аварийное завершение процесса приводят к `unknown` и остановке выпуска. Автоматической повторной отправки таких писем нет. Проверять журнал SMTP вручную; нельзя просто вернуть их в очередь. В базе сохраняются безопасные коды ошибок без ответов SMTP с персональными данными.

В каждом письме есть личная HTTPS-ссылка отписки и заголовки `List-Unsubscribe`, `List-Unsubscribe-Post`. GET показывает подтверждение и не меняет данные, чтобы сканеры почты не отписывали людей. POST, включая RFC 8058 one-click, идемпотентно исключает адрес из будущих новостных рассылок. Токен HMAC привязан к получателю и email, подписан отдельным контекстом с `BETTER_AUTH_SECRET`. При ротации этого ключа старые ссылки перестанут работать; перед ротацией нужен переходный ключ проверки. Резервный способ — ответить на письмо с просьбой отписать; такой запрос нужно обработать в таблице исключений до следующей рассылки.

Шаблоны неизменяемого выпуска загружаются из `MAILING_CONTENT_ROOT`, в production это `/app/release-mailings/autumn-2026`. Релиз должен включать HTML, plain text, `message.json` и `assets/*.png`.

Операционный CLI использует тот же сервис, что и страница сайта:

```
node apps/api/dist/mailing.js verify
node apps/api/dist/mailing.js test
node apps/api/dist/mailing.js status
MAILING_CONSENT_SOURCE="Источник согласий" node apps/api/dist/mailing.js start
node apps/api/dist/mailing.js pause
```

CLI не принимает произвольные адреса и не раскрывает базу: тест ограничен настроенным администратором, статус выводит агрегированные счётчики.

Проверки на отдельной локальной PostgreSQL-базе:

```
MAILING_TEST_DATABASE_URL=postgres://postgres@127.0.0.1:5457/mailings_test npx vitest run apps/api/test/mailings.test.ts
npm run typecheck
npm run validate:ui-copy
npm run build:api
```
