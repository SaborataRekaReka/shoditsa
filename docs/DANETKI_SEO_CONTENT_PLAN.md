# SEO-план раздела «Данетки»

Дата исследования: 17 августа 2026 года. Частотности ниже сняты в Яндекс Wordstat за 16.07–14.08.2026, все регионы и устройства. Для приоритизации использована точная форма с операторами кавычек и `!`; широкая частотность приведена только как контекст спроса.

## Цель и роли страниц

- `/games/danetki` — транзакционный интент: «данетки онлайн», запуск игры с ведущим.
- `/danetki` — информационный интент: «данетки», «данетки с ответами», общий каталог.
- `/danetki/{podборка}` — отдельный устойчивый интент и отобранный список историй.
- `/danetki/{сюжет}` — конкретная история с условием, вопросами, ответом и переходом в игру.

Такое разделение не смешивает каталог с игровой посадочной и не создаёт несколько страниц под один запрос.

## Контентный контракт

Каждая индексируемая подборка должна иметь уникальные `title`, `description`, `h1`, лид, два содержательных абзаца, сценарий игры, хлебные крошки и `CollectionPage` + `ItemList`. Списки формируются из общей библиотеки динамически:

- детские — только с явным жанром `детская`, а не все карточки для семейной аудитории;
- сложные — `difficulty=hard`;
- лёгкие — `difficulty=easy`;
- новые — 12 последних карточек по `publishedAt`, затем по редакционному рейтингу.

Минимум для сохранения качества посадочных: 8 явно детских, 8 лёгких и 8 сложных историй. Валидатор библиотеки должен блокировать сборку при падении ниже этих порогов.

## Внутренняя перелинковка и конверсия

- На общем каталоге и каждой подборке показывать ссылки на все четыре подборки с фактическим числом историй.
- На сюжетах оставлять ссылки на похожие истории и общий каталог.
- Главный CTA подборки передаёт в игру источник и имя подборки; CTA конкретного сюжета передаёт сюжет.
- Воронка измеряется событиями: просмотр каталога → переход в игру → запуск → первый вопрос → предложение регистрации → клик → успешная регистрация.

## «Альбатрос»

Одна каноническая страница `/danetki/albatros` покрывает варианты «данетка про альбатроса», «мясо альбатроса» и «суп из альбатроса». Не создавать дубли под каждый вариант названия. Названия должны быть видимы на странице, а условие и ответ — соответствовать классическому сюжету.

## Вторая итерация библиотеки

Сначала расширять существующие четыре подборки, сохраняя баланс сложности и явную детскую маркировку. После накопления данных за 28 завершённых дней проверить в Вебмастере и Search Console показы, CTR, среднюю позицию и запросы по каждой посадочной. Новую индексируемую подборку создавать только если одновременно выполнены условия:

1. есть самостоятельный подтверждённый спрос;
2. в библиотеке не менее 8 действительно соответствующих историй;
3. интент нельзя полноценно закрыть существующей страницей;
4. можно написать уникальный полезный текст без подмены списка фильтром.

Первыми кандидатами на повторную проверку остаются «интересные» и «страшные», но текущие цифры не оправдывают отдельные страницы.

## Проверка результата

- Все URL возвращают 200 и присутствуют в sitemap.
- Canonical совпадает с URL; robots — `index,follow`.
- Серверный HTML содержит уникальные заголовки, текст, карточки и JSON-LD до выполнения JavaScript.
- Неизвестные подборки не индексируются и не попадают в sitemap.
- Мобильная версия сохраняет читаемость и горизонтальную навигацию по подборкам.
- После релиза: запросить переобход пяти каталогов и «Альбатроса», затем не переписывать сниппеты минимум 14–28 дней без сигнала из фактических данных.
