# Музыка: редакционная база 0.2.0

## Источник и границы

Исходный пользовательский `music_artists_enriched (2).json` сохранён без изменения
байтов в `data/music-editorial/music-artists-enriched.v0.2.0.json`.
SHA-256: `6638fc549e0ef5bac6f3c19256f2c810a92457813fa73eb3f46c4940dec4d6b1`.
435 уникальных артистов: 249 сольных исполнителей, 186 групп.

Это **замена обычной Музыки**, не объединение со старым каталогом. Производственный
снимок до замены содержит 573 обычные карточки и 340 отдельных `kpop_artist`.
K-pop, другие игры, исторические ревизии, партии, попытки, комнаты и опубликованные
загадки дня остаются неизменными. Новые свободные игры используют новую активную
ревизию; существующая загадка дня продолжает использовать свою ревизию. Будущих
материализованных обычных музыкальных загадок на момент проверки 2026-09-02 нет.

## Преобразование

- `debut_year` → `musicDebutYear`, `debut_release` → `musicDebutRelease`. Не копировать
  их в `activityStartYear`: дебют и начало деятельности — разные значения.
  Исходное определение года допускает запасной источник Wikidata, поэтому название
  релиза при отсутствии сведений остаётся `null` (38 записей).
- `debut_decade` проверяется на соответствие году; в игре вычисляется из года.
- `languages` → `musicLanguages`, `gender` → `musicGender`: отдельные критерии.
- `entity_type`, `career_status` → `musicType`, `musicIsActive`.
- Страны: LV/MD/RO → Латвия/Молдова/Румыния; Англия → Великобритания;
  Республика Корея → Южная Корея; Королевство Нидерландов → Нидерланды;
  ФРГ → Германия. СССР остаётся отдельным историческим значением.
  Движок принимает и названия, и прежние коды стран; неизвестные исторические
  названия не отбрасываются. Проверяется наличие всех девяти критериев сравнения
  у каждой карточки, а не только корректность уже сформированных подсказок.
- Объединены только явные синонимы жанров: новая волна/нью-вейв,
  электроника/электронная музыка, традиционная поп-музыка/традиционный поп.
- Подсказка, песня, похожие артисты и игровые факты берутся из нового файла.
  Старые Last.fm-метрики и фактические значения не подмешиваются.
- `compatibility.json` сохраняет только идентичность, поисковые имена и игровые
  уровни: 256 точных совпадений по имени/алиасу, 179 новых ID. Нечёткое сопоставление
  не используется. Для новых карточек без старой сложности выбран `popular`.
- Пулы сложности: easy 136, medium 417, hard 299, expert 18. Уровни пересекаются
  согласно существующим правилам игры. `popularityScore` — технический вес уровня,
  не статистика прослушиваний.
- Девять обложек альбомов заменены на изображения исполнителей; причины и источники
  находятся в `overrides.json`. Для Комнаты культуры используется концертное фото
  с [официального сайта](https://komnatakultury.ru/), для A’Studio —
  [групповая фотография](https://commons.wikimedia.org/wiki/File:Astudio.jpg).

`verified_at` исходника — заявление источника, а не результат независимого аудита.
`dataQuality.verified` намеренно `false`. Проведены структурная проверка, проверка
соответствия исходнику, игровой совместимости и изображений; полный внешний
фактчек биографических сведений не выполнялся.

## Воспроизводимая сборка

```powershell
npx tsx scripts/music/build-editorial-catalog.ts --write
node scripts/music/audit-editorial-media.mjs
node scripts/diagnostics/verify-game-mode-release.mjs --mode=music --data-dir=music --expected=435 --min-playable=435 --criteria=musicDebutYear,musicLanguages,musicGender,countries,genres,musicType,musicIsActive --min-criteria=7 --require-poster --strict-aliases
```

Сборка формирует `music.generated.json`, библиотеку `music/items.json`, поисковый
индекс и `music/source.json`. В server web bundle полная база не публикуется.
Файлы `var/music-catalog-migration/` содержат локальные отчёты, но не входят в релиз.
Старые golden-сравнения используют фиксированный legacy-снимок, отдельно от новых
тестов всех 435 карточек.

## Безопасное переключение

Сначала полный согласованный релиз API и web через `deploy-timeweb.yml`.
Не использовать web-only deploy. В API-образ входят исходник, библиотека и
`apps/api/dist/content-replace-music-catalog.js`; CI проверяет наличие ровно 435
игровых карточек в образе.

В контейнере API сначала выполнить preview:

```sh
node apps/api/dist/content-replace-music-catalog.js --report=/tmp/music-replacement-preview.json
```

Проверить `baseRevisionId`, количества, удаляемые/добавляемые ID в полном отчёте.
После резервной копии и успешных проверок применить к **проверенному** UUID:

```sh
node apps/api/dist/content-replace-music-catalog.js --apply --activate --actor-id=<existing-admin-uuid> --expected-active=<reviewed-base-uuid> --report=/tmp/music-replacement-result.json
```

Программа проверяет совпадение release-библиотеки с преобразованным исходником,
актуальность базы, роль администратора, отсутствие неопубликованных правок и
осиротевших спецпоказов. Создаёт новую ревизию целиком в транзакции и проверяет
неизменность остальных payload/флагов. Активация выполняется штатной функцией
с защитой рабочей версии; повторный запуск идемпотентен.

Откат: штатно активировать сохранённую предыдущую ревизию в админке. Старые данные
не удаляются; код совместим с обоими форматами. Не запускать общий импорт всех
локальных библиотек поверх production: локальные каталоги других игр могут
отличаться от актуальной производственной ревизии.
