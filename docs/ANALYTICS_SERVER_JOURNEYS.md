# Серверная проверка продолжений игры

Подготовлено 26.10.2026 после read-only аудита. Методика `server-journeys-v1` добавляет поле `serverJourneys` в существующий `/api/v1/admin/acquisition-funnel?days=7|14|31`. Старые поля и их расчёты не заменяются. Выпуск и production browser check выполняются координатором; этот документ не утверждает, что релиз уже состоялся.

## Что именно измеряется

`summary.nextStarts` по-прежнему означает число органических входных когорт с клиентскими событиями start, complete и game_next_start. Эти события могут относиться к разным партиям и к тому же режиму. Подпись теперь «Продолжили игру», а не доказанный переход в другую игру.

Новый блок сравнивает текущие и предыдущие **завершённые UTC-дни**. Источник — `game_session_facts`, связанные клиентские переходы, зарегистрированные аккаунты и доступные попытки. Сотрудники и спецпаки исключены. Никаких миграций, восстановления старых событий или production-записей.

Для «Диагнозов» знаменатель — исходные партии, завершённые won/lost в соответствующем периоде, не уникальные люди. `expired` не является завершением. Два отдельных результата:

1. Повтор того же режима — новый факт партии того же владельца с `source_session_id` исходной партии, начавшийся после её завершения и до конца окна. Число таких стартов и число разных исходных партий передаются отдельно. Это **все** связанные повторы, а не прежний growth-показатель повторов только после первой завершённой партии профиля; 295 и 69 нельзя сравнивать как одну метрику.
2. Другая рекомендованная игра — исходная серверная партия, её клик, `game_next_start` с тем же `transition_id` и новая серверная партия animal/character/book того же владельца. Клик связан исходным session ID. Target mode проверяется по серверу и отличается от source mode. Порядок: source completed ≤ click ≤ target started ≤ click +15 минут, оба клиентских события и target start до конца окна. Самих клиентских start-событий недостаточно. Старые возобновлённые партии не засчитываются. Точная нижняя граница чувствительна к разнице часов; исключённые старты до клика показываются отдельно.

Конверсия — разные исходные партии с настоящим межигровым стартом / все подходящие исходные завершения. Число target-стартов дедуплицировано по серверному target session ID. Target-завершение — won/lost после target start и до конца того же окна. Разбивка organic требует хотя бы одного связанного с исходной партией события того же владельца, с `analytics_consent=accepted`, organic source и непустым acquisition ID. Это не все органические посещения Метрики.

## Первые «Персонажи» и удержание

Первая наблюдаемая партия определяется по сохранившейся истории Character владельца, с устойчивым порядком startedAt/ID. В сравнение входят старты строго до конца окна минус 48 часов. Завершение и попытки ограничены одинаковыми 48 часами после старта. Незрелые партии показаны отдельно. Удалённая строка gameplay означает неизвестное число попыток, а не ноль. Медиана первого ответа считается только по партиям с наблюдаемой попыткой; количество наблюдений видно рядом. В отличие от исследовательского SQL, округление выполняется после вычисления медианы, без предварительного округления каждой задержки.

D1/D7 — неслужебные зарегистрированные аккаунты, созданные в окне. Аккаунт входит в знаменатель, только если календарный день +1/+7 целиком закончился к правой границе. Возврат — любая публичная серверная игровая партия ровно в этот день по UTC, не любое возвращение в течение недели. При нулевом eligible доля `null`, не 0%.

## Совместимость и пропуски

- Новое поле optional для старого API/нового web. При отсутствии поля интерфейс сохраняет исторический клиентский блок с уточнённой подписью. При ошибке нового SQL возвращается `status=unavailable`, пустые периоды `null`; остальной отчёт остаётся доступен.
- При доступном новом блоке исторический клиентский блок скрыт в UI, но поля `diagnosisRecommendations` остаются в API без изменений.
- Граница protected facts читается из `app_settings[analytics.gameSessionFacts]`, первый полный день — следующий UTC-день после recordingStartedAt. Нет метаданных — coverage unavailable.
- Самое раннее наблюдаемое raw-событие и нижняя граница 38-дневного хранения передаются явно. Окно, начавшееся раньше доступного raw, помечается partial. Для previous31 это ожидаемо. Частичные counts — только наблюдаемые записи; `crossGameRate` скрывается (`null`). При partial facts также скрываются Character и D1/D7 rates. Считать отсутствие старых событий нулями запрещено.
- UI и документация называют новую версию измерения. Новые server counts нельзя трактовать как рост относительно старых client counts. Персональные ID и пользовательский ввод не возвращаются.

## Ручная сверка до выпуска

Вместо тестовых suites и локального Docker, которые пользователь просил не запускать, выполнен read-only прогон нового сервиса через существующий production API container. Код передан по stdin, SQL выполнен в `REPEATABLE READ READ ONLY` с timeout 15 секунд. Файлы и данные сервера не изменялись. Срез: 26.10, окна заканчиваются 26.10 00:00 UTC. Локальное доказательство: `.tmp/server-journeys-validation/result.json`; script/entry расположены рядом.

## Инварианты и проверка в браузере после выпуска

1. Войти администратором, открыть Overview и переключить 7, 14, 31 день. У обоих периодов границы UTC не включают текущий день. Сеть возвращает новые поля, старые summary/diagnosisRecommendations сохранены.
2. Общая карточка «Продолжили игру» не обещает другой режим. В серверном блоке повтор и другая игра имеют разные строки. Изменение периода обновляет оба столбца. При 31 дне прежний период имеет явное предупреждение; проценты для partial показывают тире.
3. CrossGame sources ≤ completedSessions; crossGameCompletions ≤ crossGameStarts; сумма byMode.starts равна crossGameStarts. Повторная доставка одного события не увеличивает distinct target session count. SameGame не включается в crossGame.
4. У Character completions ≤ mature starts; zeroAttempts + unknownAttempts ≤ starts; не считать незрелые старты отказами. Нет сохранённых попыток — unknown, а не zero. При нулевой выборке медиана и проценты показывают тире.
5. D1/D7 returned ≤ eligible ≤ accounts. Нулевой eligible показывает 0/0 и тире. Проверить текст о точном календарном дне и малой выборке.
6. Desktop и ширина 390 px: блоки читаются без горизонтального переполнения; длинные определения и подписи переносятся. На старом API без serverJourneys показывается исторический блок с ясной оговоркой. При unavailable серверный блок не показывает ложные нули.
7. После релиза сохранить SHA/время и заново сверить 14-дневный aggregate с SQL. Через 24–48 часов проверить доступность, длительность запроса и границы окон; продуктовый эффект новой методики не заявлять.
