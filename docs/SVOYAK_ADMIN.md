# Редактор «Своей игры»

Адрес: `/admin/svoyak`, пункт «Своя игра» в административном меню.
Использует штатную проверку роли, UUID и email владельца на каждом API-запросе.
Ответы не доступны через публичный каталог. Записывающие запросы проверяют Origin.

Менеджер показывает всю исходную библиотеку: 1 313 вопросов из 9 паков,
включая вопросы с медиа, неполные темы и ещё не допущенные карточки. Снимок
исходной редакции хранится отдельно от игрового каталога в приватном
`app_settings['svoyak.editor.library.v1']`. При слиянии по устойчивому ID
продовая или сохранённая администратором версия имеет приоритет. Остальные
исходные вопросы добавляются с `enabled=false`. Просмотр и импорт не допускают
их к игре и не меняют активную ревизию.

В исходном снимке 930 вопросов с медиа. 1 116 уникальных исходных и выбранных
редактором файлов сохранены в закрытом хранилище (332 456 336 байт). Для 195
медиавложений локального файла нет: исходная ссылка и статус недоступности
остаются видимыми. Доступность файла не означает, что его содержание проверено.

Приватный bind mount `/srv/shoditsa/svoyak-library` не находится под `/media`.
Оригиналы выдаёт только авторизованный `/api/v1/admin/svoyak/library/media/:sha`,
с поддержкой HTTP Range для аудио/видео. Файлы явно допущенного вопроса при
публикации копируются в публичное игровое хранилище; остальные не раскрываются.
Подробная исходная история и источники загружаются отдельно по требованию.

Поиск работает по формулировке, ответу, вариантам зачёта, теме, паку и ID.
Фильтры: пак, интерес, допуск и наличие медиа. Вопросы можно создавать,
дублировать, переносить между паками, удалять из черновика и снимать с игры.
Паки можно создавать, переименовывать, снимать целиком с игры и удалять пустыми.
Исходные карточки сохраняются в библиотеке; вручную созданные можно удалять.

Предпросмотр использует `SvoyakQuestionContent`, общий с настоящей комнатой.
Есть вопрос игроку, раскрытый ответ, ключ ведущего, оригинал и ширина телефона.
Показаны статус исходной редакции, причины недопуска, оригинальные тексты,
медиа и история. Есть фильтр по статусу проверки; поиск учитывает оригиналы.
Стоимость в превью иллюстративная: сложность × 100. Фактическая стоимость
назначается сборщиком по месту вопроса и раунду.
Медиа показываются по порядку, с ручным запуском аудио/видео. Ошибка загрузки
видна прямо в превью. Файлы до 18 МиБ: JPEG, PNG, WebP, MP3, WAV, OGG, MP4,
WebM. Изображения конвертируются в WebP. Можно добавить HTTPS-ссылку.
Удаление медиа убирает связь с вопросом; файл сохраняется для старых партий.

## Сохранение и публикация

Сборщик сохраняет полные авторские темы. Вопросы из неполных тем объединяются
по выбранной категории в явно названную сборную тему. Небольшой остаток
присоединяется к целой теме той же категории с переименованием в сборную.
Каталог и сборщик используют общий алгоритм группировки: готовая карточка
не исчезает только из-за того, что её исходная тема неполна. Совпадение коротких
условий медиавопросов считается дублем лишь при совпадении вопросных медиа.
Ответные вложения не участвуют в этом сравнении.

`scripts/content/publish-svoyak-reviewed.ts` публикует только неизменённые
карточки с завершённой проверкой из приватного снимка. Проверяет восемь
решений допуска, отсутствие блокеров, совпадение с текущим черновиком и
контрольные суммы файлов. Перед атомарной активацией собирает обычную игру
и отдельную тему каждой категории. Активную ревизию и конкурентные правки
защищают общий advisory lock и версии. Исходные решения и архив сохраняются.

Правки в форме сразу видны в превью. «Сохранить черновик» сохраняет весь
рабочий набор в `app_settings['svoyak.editor.workspace.v1']`. После этого
можно перезагрузить страницу. Несохранённые правки защищены предупреждением
при уходе; до сохранения публикация заблокирована.

Для нового допуска исходного вопроса или изменения ранее допущенного
содержания нужны восемь явно отмеченных проверок: facts, clarity, style,
answers, category, safety, duplicates, media. Правки содержания сбрасывают
чек-лист и допуск в форме. Сервер проверяет их при публикации. При отказе от
исходных медиа нужна самостоятельная текстовая версия; недоступные медиа
требуют явного решения о замене. Это пользовательские решения, а не
автоматический фактчекинг. Оригинальные решения не переписываются.

«Опубликовать» проверяет возможность собрать стандартную игру из трёх полных
тем с учётом дублей, создаёт новую ревизию и атомарно переключает активную.
Активная ревизия никогда не редактируется напрямую. Старая остаётся retired
для уже начатых партий. Устаревший ещё не запущенный план потребует пересборки.
Пустые паки и интересы сохраняются в редакторе, но отфильтровываются из лобби.

Сохранение, публикация и сброс используют один advisory lock и проверку
версии черновика и исходной ревизии. Конкурирующая вкладка получает 409;
её правки не перезаписывают новую базу. Операции пишутся в audit_log.
«Удалить черновик» возвращает редактор к опубликованной версии.

## Проверка

`apps/api/test/svoyak-admin.integration.test.ts` требует отдельную локальную БД
`svoyak_editor_test`; тест отказывается работать с другим именем или хостом.
Покрывает защиту API, конфликты, неизменность активного контента, атомарный
выпуск, запрет неиграбельной базы, безопасные URL, загрузку файла, редактирование
паков и отсутствие медиа ответа у игрока до раскрытия.

## Перенос полного фонда

`scripts/content/export-svoyak-library.py` делает согласованные SQLite backup
из read-only подключений, читает действующие редакторские правки, оригиналы,
восемь проверок, media selections и историю. Исходные SQLite и SIQ не меняются,
сеть и модель поиска не запускаются. Файлы копируются с проверкой SHA256.
Сырые данные и архивы не попадают в Git или web-артефакт.

`scripts/content/import-svoyak-editor-library.ts` проверяет все файлы по SHA256,
требует существующего администратора, под общим advisory lock создаёт только
приватный снимок и запись аудита. Существующий снимок нельзя перезаписать
повторным импортом. Рабочий черновик администратора не заменяется.

Выпуск полного фонда выполняется `scripts/deploy/svoyak-library-timeweb.sh`:
API и web вместе, приватный read-only mount, копия таблиц редактора и конфигурации,
проверка доступности резервной копии вне сервера, совпадение SHA API/worker/web,
неизменность активных игровых каталогов. Миграция схемы не требуется.

## Невосстановленные медиа и реконструкция назначения

`/admin/svoyak?mediaRecovery=unresolved` открывает отдельный список. Есть поиск
по паку, вопросу, ключу и исходному URL, причина сбоя, тип/фаза, переход к карточке
и CSV всех вложений. API списка защищён штатной проверкой администратора.

31 октября 2026 повторно выполнены GET-запросы по всем 195 исходным URL
`openquiz.hb.bizmrg.com`; все 195 получили HTTP 404. Это 90 вопросов. Файлов
восстановлено 0; рабочие версии вопросов, их медиа и допуск не менялись.

Для каждого вложения отдельно описано ожидаемое содержимое по исходным теме,
ключу, типу и фазе SIQ. Это предположения для подбора редакторской замены,
а не найденные оригиналы и не фактчекинг. Во всех записях стоят
`inferenceOnly=true`, `exactOriginalKnown=false`. Уверенность относится к
назначению вложения; точные кадры, записи, монтаж и таймкоды неизвестны.
Новые описания не добавляются в игровое условие и не раскрываются игрокам.

Скрипты `recover-svoyak-media.py` и `describe-svoyak-missing-media.py` создают
отдельный журнал запросов и описания, не меняя SIQ и SQLite. Скачивание разрешает
только публичные HTTP(S) адреса, проверяет редиректы и ограничивает размер/время;
найденный файл должен распознаваться как настоящее медиа.
`record-svoyak-media-recovery.ts` проверяет каждый URL по приватному снимку,
сохраняет отчёт в `app_settings['svoyak.editor.media-recovery.v1']` и аудит,
сохраняя предыдущий отчёт. Отчёт с найденными файлами не принимается без
их отдельного проверенного импорта. Повторный запуск с тем же временем проверки
и подготовки контекста идемпотентен.

Выпуск: `scripts/deploy/svoyak-media-recovery-timeweb.sh`, совместные API/worker/web,
резервная копия редакторских таблиц вне сервера и проверка неизменности игровых
каталогов. Восстановление назначения не меняет статус допуска.
